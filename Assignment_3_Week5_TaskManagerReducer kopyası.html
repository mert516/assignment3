Abbreviations and Key Terms

action
A plain object that describes what happened, such as { type: 'remove', id }. The reducer decides what it means.
AI
Artificial Intelligence, as in AI coding assistants.
derived state
A value you compute from state while rendering, such as the filtered list, instead of storing it.
discriminated union
A TypeScript type made of several object types that each have a different type string, so the compiler knows which other fields exist.
dispatch
The function useReducer returns. You call it with an action to ask the reducer for a state change.
Moodle
The course platform: you download materials and upload assignments there.
npm
Node Package Manager, which installs packages and runs project scripts.
pure function
A function whose result depends only on its arguments and which changes nothing outside itself.
reducer
A pure function (state, action) => nextState that holds all the rules for changing state.
TS
TypeScript, JavaScript with static types.
Vite
The build tool and development server used by the course projects.
Vitest
A test runner that works with Vite projects.

Where to start

The sample is a complete project in the starter/ folder that comes with this handout. Nothing to generate or copy: open a terminal in the folder and run these commands. You need Node.js 20.19 or newer.

Terminal
npm install
npm run dev

It is a small Task Manager with a reducer, a row component and an app that keeps the state with useReducer. It also has a filter.ts for you to fill in. Work inside this project and build on it.

This is the sample reducer (src/taskReducer.ts). You will change it. The Action type is a discriminated union, and a reducer must stay pure: the caller creates the id with crypto.randomUUID(), not the reducer.

src/taskReducer.ts (the sample)
export type Status = 'todo' | 'in-progress' | 'done'
export type Task = { id: string; title: string; status: Status }

export type Action =
  | { type: 'add'; id: string; title: string }
  | { type: 'advance'; id: string }
  | { type: 'remove'; id: string }

const NEXT: Record<Status, Status> = {
  todo: 'in-progress',
  'in-progress': 'done',
  done: 'todo',
}

export function taskReducer(tasks: Task[], action: Action): Task[] {
  switch (action.type) {
    case 'add':
      return [...tasks, { id: action.id, title: action.title, status: 'todo' }]
    case 'advance':
      return tasks.map((t) =>
        t.id === action.id ? { ...t, status: NEXT[t.status] } : t,
      )
    case 'remove':
      return tasks.filter((t) => t.id !== action.id)
  }
}

Requirements

Your solution meets all seven requirements.

  1. Change the state from Task[] to an object: type State = { tasks: Task[]; filter: Filter }, where Filter is 'all', 'todo', 'in-progress' or 'done'. Export State, an initialState (no tasks, filter 'all') and the reducer taskReducer(state: State, action: Action): State. App uses useReducer(taskReducer, initialState).
  2. Keep the three existing actions (add, advance, remove), now working on state.tasks, and add two new ones: { type: 'setFilter'; filter: Filter } and { type: 'clearDone' }. clearDone removes every task whose status is done and keeps the filter. Add a Clear done button to the screen.
  3. The reducer is pure and complete. It never changes the old state: it returns a new object, and new arrays and new objects for anything that changes. It does not call Math.random(), Date.now() or crypto.randomUUID(). Its switch covers every action type, so TypeScript reports an error if you add an action and forget to handle it.
  4. Write two pure functions in filter.ts with no React in the file: filterTasks(tasks, filter) returns the tasks for the chosen filter ('all' returns every task), and countByFilter(tasks) returns a number for each of all, todo, in-progress and done.
  5. Add a filter bar with four buttons: All, To do, In progress, Done. A click dispatches setFilter. The button of the active filter looks different from the others. The list shows only the tasks that match.
  6. Show the count next to each button, for example In progress (2). The counts and the visible list are derived while rendering with your functions from R4. Never keep a second filteredTasks or counts in state. Everything keeps working with a filter on: you can add, advance and delete, a task that no longer matches the filter leaves the list, and an empty list shows a message such as “No tasks here.”
  7. The project passes npm run build (which type-checks in strict mode) with no errors, and it uses no any.

Bonus 1: Undo 5+ points

Add an Undo button that reverts the last change to the tasks. This changes the state shape again, which is the point: the reducer is the only place that knows about it.

  • Keep the earlier task lists in the state, for example past: Task[][]. Every action that changes tasks pushes the old list; a new { type: 'undo' } action pops the last one back. Undo does nothing when there is nothing to undo.
  • Changing the filter is not undoable. Undo after clearDone brings the cleared tasks back.
  • The button is disabled when past is empty.

Troubleshooting

What you seeWhy, and what to do
The list does not update after Add or NextSomething changed state by mutation. The reducer must return a new object with new arrays: [...state.tasks, t], state.tasks.map(...), state.tasks.filter(...).
The counts or the list are wrong after a delete or a changeYou probably stored a filtered list or counts in state, and it went stale. Compute them from state.tasks while rendering.
Property 'filter' does not exist on type 'Task[]'Some code still treats the state as an array. Use state.tasks and state.filter.
Type 'undefined' is not assignable to type 'State'One case in the switch returns nothing, or an action type is not handled. Every branch must return a State.
Cannot update a component while rendering a different componentYou called dispatch during render. Call it only inside event handlers.
TS1484 or verbatimModuleSyntax errors on importsImport types with import type or import { type Task }.
The Vite page is blankOpen the browser console (F12). A thrown error there is usually an import path typo or code still using the old array state.
